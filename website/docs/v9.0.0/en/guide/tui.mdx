# A3S Code TUI

`a3s code` is the interactive terminal workspace for A3S Code. It is shipped by
the [`a3s` CLI](https://github.com/A3S-Lab/a3s), drives the Rust
`a3s-code-core` runtime, and renders the runtime event stream with
[`a3s-tui`](https://github.com/A3S-Lab/TUI).

Use the TUI when you want the ready coding-agent product in a terminal. Use an
A3S Code SDK when you are embedding the same runtime in another host, runner,
IDE bridge, or controlled product surface.

## Surface Map

| Surface       | Repository                                      | Responsibility                                                                                                     |
| ------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| A3S Code SDKs | [A3S-Lab/Code](https://github.com/A3S-Lab/Code) | Rust runtime crate plus Node.js, Python, and Go SDKs.                                                              |
| `a3s code`    | [A3S-Lab/a3s](https://github.com/A3S-Lab/a3s)   | Terminal coding-agent application that drives `a3s-code-core` sessions.                                            |
| A3S Use       | [A3S-Lab/Use](https://github.com/A3S-Lab/Use)   | Independently released Browser, Office, OCR, and signed application capabilities projected through MCP and Skills. |
| `a3s-tui`     | [A3S-Lab/TUI](https://github.com/A3S-Lab/TUI)   | Terminal UI framework used by the CLI. It is the renderer and component library, not the agent runtime.            |

## Install And Start

Run the installer for your platform:

<Tabs>
<Tab label="macOS / Linux">

```bash
curl --proto '=https' --tlsv1.2 -LsSf \
  https://raw.githubusercontent.com/A3S-Lab/a3s/main/install.sh | sh
```

</Tab>
<Tab label="Windows">

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor [Net.SecurityProtocolType]::Tls12
irm https://raw.githubusercontent.com/A3S-Lab/a3s/main/install.ps1 | iex
```

</Tab>
</Tabs>

The scripts select the release archive for the current system and architecture
and verify its SHA-256 digest. You can also use
`brew install a3s-lab/tap/a3s` or `cargo install a3s`.

Run the CLI from the workspace the agent should inspect:

```bash
a3s code                      # interactive TUI
a3s code --worktree [NAME]    # start in an isolated Git worktree
a3s code resume               # resume the newest session
a3s code resume <session-id>  # resume a selected session
a3s self update               # upgrade the CLI (same updater as /update)
```

Global flags apply to every command: `-C <PATH>` runs as if started in another
directory, `--config <PATH>` selects one explicit ACL file, and `--offline`
disables network access and first-use downloads.

## Configuration

Configuration is A3S ACL. The CLI resolves it as follows:

1. An explicit `--config <PATH>` or `A3S_CONFIG_FILE` is used alone.
2. Otherwise the user file `~/.a3s/config.acl` and the nearest
   `.a3s/config.acl` found while walking upward from the workspace are merged as
   layers, with the workspace layer applied last.

A workspace layer can configure the agent, but it cannot reroute credentials or
source-code egress; host-owned egress capabilities read only the trusted
explicit and user layers.

On first launch, when no explicit, workspace, or user config exists, the CLI
writes a starter `~/.a3s/config.acl` and opens it in the built-in editor. Use
`/config` later to edit the active file. Keep real keys and private endpoints
out of committed files; see [Providers](/guide/providers) for model and
credential configuration.

## Modes

Shift+Tab cycles the run mode: Default, Plan, Reviewer, Auto, Yolo.

| Mode     | Behavior                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------- |
| Default  | Risk-aware. Safe reads run quietly; side effects ask for confirmation.                                                  |
| Plan     | Strict read-only planning. Implementation starts only after review. `/plan` and `/ask` select it.                       |
| Reviewer | Arms an asynchronous claim-vs-record reply verifier. It does not own the main agent stream. `/reviewer`.                |
| Auto     | Non-interactive execution. Hard policy and workspace denials still win. `/auto`.                                        |
| Yolo     | Auto-allows high-risk review candidates. Critical denials, protected paths, and leaving the sandbox still win. `/yolo`. |

`/permissions` changes the next-turn mode and lists exact grants. Project grants
are stored in `.a3s/permissions.acl`. `/sandbox` and `a3s code sandbox status`
report whether the host Bash sandbox is ready.

## Input And Keys

| Input        | Action                                                                     |
| ------------ | -------------------------------------------------------------------------- |
| `! <cmd>`    | Run a shell command directly.                                              |
| `? <query>`  | Shortcut for `/research <query>`.                                          |
| `@<path>`    | Reference a workspace file; image files become visual attachments.         |
| `$<skill>`   | Mention a Skill. Alt/Option+Enter keeps it sticky until Esc or `/unstick`. |
| Ctrl+V       | Attach an image.                                                           |
| Enter        | Send. While a turn is running, append the message to the FIFO queue.       |
| Ctrl+O       | Send now: cancel the active turn and promote this prompt.                  |
| Ctrl+J       | Insert a newline. Shift+Enter also works when the terminal reports Shift.  |
| Up / Down    | Recall session history; move the selection inside menus.                   |
| PgUp / PgDn  | Scroll the transcript or the help panel.                                   |
| Shift+End    | Jump to the latest output.                                                 |
| Ctrl+T       | Expand full tool output and diffs.                                         |
| Ctrl+R       | Fuzzy-search prompts from the current session.                             |
| Ctrl+G       | Review the DiffView for the latest turn's file edits.                      |
| Ctrl+B       | Inspect delegated tasks, recent output, and safe cancellation.             |
| Esc          | Interrupt the running turn, close panels, or clear a sticky Skill.         |
| Ctrl+C twice | Quit.                                                                      |

`/help` opens the complete grouped reference.

## Effort Profiles

`/effort` selects a budget profile for the session:

| Level       | Thinking budget | Tool rounds | Continuation turns | Parallel tasks |
| ----------- | --------------- | ----------- | ------------------ | -------------- |
| `low`       | 2048            | 240         | 4                  | 4              |
| `medium`    | 8192            | 800         | 8                  | 8              |
| `high`      | 16384           | 1200        | 12                 | 8              |
| `xhigh`     | 32768           | 1800        | 16                 | 8              |
| `max`       | 65536           | 2400        | 24                 | 8              |
| `ultracode` | 65536           | 3200        | 32                 | 8              |

Parallel tasks are capped at 8 for interactive provider concurrency.

## Sessions And Worktrees

Sessions are stored per workspace under `.a3s/tui/sessions`, and resumable UI
state under `.a3s/tui/session-state`. Sessions from the older
`.a3s/tui-sessions` location are migrated on launch.

`a3s code session list|show|export|delete` manages stored sessions without
touching workspace files.

`a3s code --worktree [NAME]` and `/fork worktree` create an isolated Git
worktree under `~/.a3s/worktrees` on a branch named `a3s/fork-<name>`. Without
a name, the launch identity is generated.

## Deep Research

`/research <query>`, `? <query>`, and `a3s code research <query>` start the
same deep-research runtime. Each run records a journal at
`.a3s/research/runs/<run-id>/journal-v2.jsonl`; the published report is written
as `report.md` and `index.html`. `/research status|explain|replay|diff` reads
the journal for diagnostics.

## A3S Use

Browser, Office, and OCR capabilities come from A3S Use and run through a
dedicated Use worker that may call only `mcp__use_*` and `use_tool_*` tools.
`/use` shows the live registry, MCP connections, Skills, and providers;
`/use repair` prints explicit repair commands without changing anything.

```bash
a3s install use --source release
a3s install use/browser
a3s install use/office
a3s install use/ocr
a3s use ocr doctor --json
```

## Headless Smoke

Set `A3S_CODE_TUI_SMOKE=1` to run one prompt through the same session stream
the TUI uses, without a terminal UI. `A3S_CODE_TUI_PROMPT` sets the prompt; a
leading `?` runs deep research and a leading `!` runs a shell command. A
headless process has no human authority, so unexpected confirmation requests
are rejected.
