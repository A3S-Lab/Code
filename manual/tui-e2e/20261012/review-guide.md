# 三角色评审与测试排期

本页用于评审和排期。具体步骤、前置和判据以三份用例表及 `catalog.json` 为准；本页不增加或重复计算用例，也不代表执行结果。

实际运行结果见 [选定用例执行状态](execution-status.md)。历史候选的 8/2、9/1 和 SOLO 结果保持原记录，未归因并发。最新驱动等待实际 ACP 请求终结，选定完整十条真实 TUI 门禁在同一冻结候选连续三次 10/10。四次编码请求的独立 Run、实际失败检查、后续绑定验证均有证据；这没有执行完 RT10 全部五例、完整 P0、平台/模型矩阵或 1,020 条目录。

实际 A3S Test ACL 引擎随后对直接 Bash/background 拒绝恢复各运行三次，均通过。任务文件变体省略必需工具调用的失败仍开放；精确后台 SOLO 通过不能改写首轮失败，Bash SOLO 的观察器失败也不能算完成。三角色须分别验收“实际调用已知拒绝后可继续”和“按任务文件执行指令”，不能用屏幕确认词替代工具证据。详情见 [ACL 引擎记录](../../../../../docs/evidence/code-harness/20261012-tui-acl-native-refusal/OUTCOME.md)。

## 三个角色分别验收什么

| 功能域 | 架构师 | 产品经理 | 测试工程师 |
| --- | --- | --- | --- |
| 启动与配置 | 验证宿主和工作区的权威边界、候选版本组合 | 首次启动能完成任务；配置错误可定位和修复 | 隔离 home，冲突 ACL、失效凭证、链接/FIFO、版本错配负例 |
| 输入与发现 | 提交字节、附件身份和命令分发正确 | 草稿不丢；输入与帮助符合当前能力 | 中文/emoji/多行/粘贴/快捷键；比对实际用户消息；防重复提交 |
| 会话与历史 | 持久身份、项目 scope、重放和删除边界正确 | 能找回上下文；切换不串内容；导出准确 | 两个带独立随机标记的会话；重启、损坏历史、删除、导出产物检查 |
| 模型与凭证 | 运行捕获的路由与配置一致，秘密不进入事实和展示 | 选择项与真实模型一致；失败不会静默换路由 | 核对实际 adapter/model 请求、token usage；脱敏和并发写配置反证 |
| 轮次与恢复 | invocation、generation、回执、效果和完成门一致 | 拒绝或取消后可继续；成功、失败、未验证状态准确 | 真模型连续十轮，故障前后基线、晚到事件、独立 checker 和 SOLO 归因 |
| 文件与检索 | 路径、大小、类型、授权和索引 scope 有界 | 读写和搜索结果有来源；部分失败可理解 | 随机 canary、精确字节/行号、黄金语料；验证越界与无泄漏 |
| 命令、Git 与网络 | 资源所有权、原生执行资格、SSRF 和变更归属可证明 | 输出、退出码、冲突和取消反馈准确 | 临时 Git 仓库、拥有进程树、公网测试端点；禁止触碰共享仓库和操作者进程 |
| 扩展与委派 | 能力按正式启动链开放；子运行和 MCP 权限不扩张 | 可发现、可用、不可用和失败有准确反馈 | 真技能/子模型/MCP/语言服务；目录换代、父取消、交叉身份和 scope 负例 |
| 界面与终端 | 本地动作无意外模型请求或外部副作用；终端状态恢复 | 可读、可导航、可取消；窄屏和中文可用 | 不同尺寸、主题、鼠标、终端能力；保留视口并核对恢复后的模式 |
| 设置与禁用入口 | 所有入口受同一能力与权限门约束 | 设置预览/取消/持久化一致；禁用能力不误导用户 | 每项至少五例；手输、别名、快捷键、菜单、重连后复查；零禁止副作用 |
| 安全与耐久 | Unknown 只由身份绑定证明结算，清理不会误伤其他会话 | 长任务持续可用；恢复不会丢约束或假成功 | 注入崩溃、重放和日志缺口；50 轮、2 小时、双会话及资源斜率 |

共同验收链：**用户操作 → 实际协议和运行事实 → 独立产物检查 → TUI 终态**。三者不一致即不通过。只出现“完成”文字、模型给出正确猜测、屏幕有关键字，都不足以验收工具功能。

## 先处理当前轮次报错

首个回归包必须覆盖 RT10 的全部五例，不能只证明正常读取：

| 用例 | 核心操作 | 架构和产品通过条件 |
| --- | --- | --- |
| TUI-RT10-01 | 已知未执行的 bash 拒绝后读取随机文件 | Denied + Complete + 零变化；下一轮成功；Unknown=0 |
| TUI-RT10-02 | 已知未执行的后台启动拒绝后继续 | 无子进程、无写入；下一轮不受虚构债务影响 |
| TUI-RT10-03 | sandbox 初始化已知失败后连续交替任务 | 每轮明确拒绝或完成；不会持续触发假 Unknown |
| TUI-RT10-04 | 已派发工具失去结果证明，同时带有相同报错文本 | 保留原 invocation 的 Unknown/Incomplete；已知退出失败按原始回执判断，不能按文字清债 |
| TUI-RT10-05 | hook 已产生写入，再使后端不可用 | 保留真实变化及其身份；不能冒充零副作用或 Complete |

多轮编码须区分“检查执行后失败”“执行前拒绝”和“最终验证通过”。只修一项的检查点不得要求 Verified；须等待实际 ACP 请求终结再提交下一轮，并核对不同 Run 身份。检测到 `Turn failed` 只能证明界面报告失败，不能替代实际 checker 退出码或身份结算。最新四请求驱动已按此合同重写并连续三次通过；独立审计重算效果摘要，30 份篡改副本均被拒绝。单提示长任务另证真实 fail→partial-fail→pass；四请求 fixture 的首轮只诊断，不冒充执行了初始 checker。完整目录继续按原判据执行，不降低门槛。

随后执行 RT07、RT09、RT11 和 SC03 的取消、断连、验证及重放反证，再跑 RT01/RT02 的真实编码闭环。拒绝后恢复通过不能替代“实际修改 → 实际检查失败 → 修复 → 检查通过”的正向编码资格。

## 实施包与退出条件

| 顺序 | 工作包 | 依赖 | 退出条件 |
| --- | --- | --- | --- |
| 1 | 固定候选、运行时入口盘点、PTY 与证据驱动 | 实际发布支持声明、有效 ACL 和 runner | 命令/设置/菜单/工具目录映射无缺口；未知入口先补例；配置不足明确失败或 BLOCKED |
| 2 | 当前报错和真实编码主链 | 包 1；合格模型及对应平台执行能力 | RT10 五例、恢复反证、连续十轮、双缺陷独立 checker 全部满足判据 |
| 3 | 本地输入、会话、显示、设置和入口限制 | 包 1，恢复基线可用 | 开放功能每项至少五例完成；菜单与快捷键无旁路；草稿、配置、终端状态准确 |
| 4 | 文件、检索、Git、网络与条件扩展 | 包 2；各实际宿主能力 | 真模型和真实产物一致；条件能力先证明可达；无模拟宿主替代通过 |
| 5 | 跨平台、跨真实 adapter、故障与耐久 | 前四包、相应 runner 与配额 | P0 模型链在两个真实 adapter 各至少三次；声明平台逐一证明；50 轮与 2 小时基线完成 |
| 6 | 同一候选发布审查 | 完整结果及开发规范门 | 无未解决 P0/P1；所有声明可用功能每项五例通过；依赖和必需 gate 通过；证据可追溯到同一候选 |

每个工作包分配维护责任人、评审人、候选摘要、运行预算和缺陷链接，再安排日期。未核对实际 runner/配额/平台前不承诺执行天数。失败、重跑、BLOCKED 和 NOT_RUN 分别报告；执行结果另存，规划目录保持 PLANNED。

发布审查必须分别展示：开放功能覆盖、限制检查覆盖、基础用例执行、平台/模型展开结果、未解决缺陷。305 条限制用例不能用于提高正向功能通过率。基础用例 1,020 条与实际运行次数分别统计。
